# Строгая проверка поддерживаемого кода

[Конечный состав](../typecheck/inventory.json) перечисляет собственные исходники,
инструменты, примеры, тесты и исполняемые программы тестовых сценариев. Проверка
сопоставляет этот список с `git ls-files`; новый или удалённый исполняемый файл
требует явного изменения состава. Вид проверки выводится из пути и языка, поэтому
собственный файл нельзя произвольно перевести в исключения.

| Состав | Проверка |
| --- | --- |
| TypeScript, включая примеры, инструменты, тесты и программы сценариев | Deno `check` с `typecheck/deno.json` |
| `browser/navigation.js` и используемая часть браузерного API | Deno `checkJs`, DOM и `typecheck/browser.json` |
| `tests/browser.cjs` | TypeScript `checkJs`, Node/Playwright и `typecheck/node.json` |
| Сохранённые Lua-фильтры, словарь и тестовые программы | LuaLS с определениями Pandoc/Quarto из поставки Quarto |
| Shell-программы тестовых сценариев | ShellCheck со всеми уровнями диагностики |

`strict`, `noUncheckedIndexedAccess` и `exactOptionalPropertyTypes` применяются
ко всем TS/JS проверкам. Конфигурации также проверяют возвраты функций; Deno
проверяет переопределения методов и переходы между ветками `switch`. Конфигурации
проверок находятся отдельно от авторских проектов и не меняют запуск расширения.

`vendor` содержит сторонний код и не редактируется. `observability/bridge.ts` и
`observability/bridge.lua` принадлежат каноническому владельцу наблюдения; их
самостоятельная проверка делегирована этому владельцу. Импортируемые типы моста наблюдения
по-прежнему участвуют в проверке собственных потребителей. Наличие исключения
не является утверждением о готовности канонического моста наблюдения.

## Запуск

Для JS-проверки нужны зависимости из закреплённого `package-lock.json`:
TypeScript 6.0.3, `@types/node` 26.6.6 и Playwright 1.62.1. Для Lua нужен
`lua-language-server` 3.19.2, для сценариев оболочки — ShellCheck 0.11.0. Команды выполняются
из корня рабочего каталога:

```sh
npm ci --ignore-scripts
quarto run tools/generate-parse5-types.ts --check
quarto run tools/check-types.ts --typescript
quarto run tools/check-types.ts --browser
npm run check:node
quarto run tools/check-types.ts --lua
quarto run tools/check-types.ts --shell
```

Lua проверяется общим инструментом `quarto-course-performance@05803ba2ee66171cec12c5fb9027da2642e5518a`.
По умолчанию он берётся из соседнего `../quarto-course-performance`; переменная
`PERFORMANCE` задаёт другой рабочий каталог той же закреплённой редакции.
Обёртка передаёт конечный собственный список `--scope`, точное исключение
канонического моста наблюдения и каталог его типов. Собственного движка LuaLS
и установщика здесь нет.
Каталоги Pandoc/Quarto определяются общим инструментом через `quarto --paths`.
`LUA_LANGUAGE_SERVER` при необходимости задаёт абсолютный путь к LuaLS 3.19.2.
Для CI применяется общий `tools/setup-lua-ci.sh` из того же рабочего каталога Performance:
он принимает новый абсолютный каталог, проверяет SHA256 и версию установки.
Контрольный `--probe` принадлежит тому же каноническому инструменту, а не локальной
копии настроек. Строгие группы `type-check`/`strong`, диагностика `no-unknown`, проверки `nil`,
объединений типов и формы таблиц сохраняются;
внешний мост наблюдения подключён как библиотека и не объявляется собственной проверкой.

Команды типов не рендерят проекты и не запускают браузер. Они не заменяют
проверки действительной установки, локальной/полной публикации, импортов, навигации и
контекста нативных обработчиков. Эти сценарии остаются отдельными проверками.

## Границы данных и дерево HTML

JSON остаётся `unknown` до существующих проверок каталога, конфигурации или
конкретного потребителя. Публичные `Catalog`, `Import`, `Exports` и `Target`
выводятся из действительных результатов проверок и проекции импорта. Второй схемы
каталога нет. Обязательные нативные метаданные HTML проверяются до создания целей;
ошибка сохраняет `QRC.OUTPUT_INVALID`, выходной путь и имя атрибута.

HTML использует реальный тип дерева parse5, включая узлы `doctype`, пространство имён и
связи родителей. Обработчик ссылок создаёт необходимые узлы штатным адаптером parse5;
поиск получает то же изменённое дерево. Дополнительного разбора HTML нет.

Deno не разрешает относительные `.js` импорты внутри исходных Node-деклараций
из `vendor` как `.d.ts`. Поэтому `tools/generate-parse5-types.ts` создаёт автономную
проекцию деклараций в `_extensions/reference-catalog/types`. Источники — только
имеющиеся сторонние parse5 7.3.0 и entities 6.0.1; версии проверяются. Генератор
сохраняет исходную структуру путей, декларации и лицензии, меняя только
относительные спецификаторы импорта `.js` на `.d.ts` и добавляя указание происхождения.
`--check` сравнивает весь результат с этими источниками. Во время исполнения по-прежнему
используется прежний сторонний parse5; npm-загрузка типов расширению не требуется.
Проекцию не редактируют вручную.
