# Архитектура QRC

* `domain` — модель каталога, ключи и стили, адресация, отбор экспорта; без запуска процессов и Quarto.
* `infrastructure` — чтение конфигурации, импорт JSON, HTML-адаптер, разрешение ссылок и запись каталога.
* `entrypoints/post.ts` — явная точка завершения самостоятельной сборки.
* `entrypoints/publication.ts` — структурный адаптер для координатора публикации; зависимость от его исходного кода отсутствует.
* `lua` — стандартные фильтры Quarto: ссылки и обнаружение целей; список типов находится в `constants.lua`.
* `browser` — раскрытие скрытых HTML-блоков и переход к фрагментам Reveal.

Координатор вызывает `metadata({namespace, format})` до рендера документа и `finalize({root, stage, quarto, config, members, portal?})` после получения всех результатов. Первый вызов возвращает фильтры и пространство имён участника. Для корневого портала `namespace` отсутствует (`undefined`): адаптер возвращает фильтры без переопределения `reference-catalog`, сохраняя авторское пространство имён корневого проекта. Второй вызов обрабатывает готовые HTML, обновляет ссылки в поисковом индексе и записывает каталог. Порядок рендера подпроектов не ограничивает двусторонние ссылки.

Необязательное поле `portal: {input, output}` — структурный выбор фактического портала из контекста координатора. QRC доверяет этому контексту; принадлежность путей попытке, штатный рендер и сохранность опубликованного результата обеспечивает координатор. QRC не определяет пространство имён по `input`, `output` или произвольным страницам: оно берётся только из корневой конфигурации и проверяется перед связыванием. Страницы и цели по-прежнему читаются из общего `stage`, а не из отдельного output портала.

Для корневого портала adapter также получает фактическую `config` координатора. Если её штатный список `filters` уже содержит `reference-catalog`, extension contributions сами подключают фильтры и shortcode: adapter возвращает пустой overlay, сохраняя всю авторскую цепочку и пространство имён. Иначе он добавляет прежние QRC фильтры/shortcode без namespace override. Участник с собственным namespace по-прежнему получает прежний overlay; наличие QRC в outer config не подменяет его отдельную native конфигурацию. Adapter не удаляет фильтры и не распознаёт произвольные цепочки по тексту исходников; допустимость Core цепочки остаётся Core-проверкой.

QRC не определяет курсы, задания, оценивание, оформление, корневую страницу, PDF или политику публикации. Стили ссылок определяются единственным JSON-словарём в `vocabulary/reference-styles.json`. Из него создаются статические проекции TypeScript, Lua и CUE; проекции не редактируются вручную. TypeScript сохраняет точный литеральный тип стиля. `tests/boundaries.ts` сравнивает файлы с детерминированным результатом генерации, без разбора программного кода. Перечень типов целей Quarto используется только Lua и остаётся в `lua/constants.lua`.
