# Диагностика каталога ссылок

Ошибка QRC начинается со стабильного ID и русского объяснения. Затем выводятся
доступные `источник`, `ID`, `поле`, связанные объекты и подсказка. Сообщение
указывает выбранный каталог, namespace и цель, а не произвольный файл из
предыдущей сборки. Соглашение действует в самом расширении; отдельного runtime
ошибок, сериализованного отчёта или генерируемого реестра нет.

## Источник, вход и результат

**Вход** — авторский QMD и конфигурация штатного проекта Quarto. Lua знает имя
текущего QMD и указывает его при отказе разметки ссылки. **Источник импорта** —
выбранный `imports.<псевдоним>.source`: путь к JSON или HTTP(S) URL. Он может
находиться вне проекта. `namespace` импорта выбирает пространство производителя,
а ключ импорта задаёт локальный псевдоним для ссылки.

**Результат** — текущий HTML внутри `stage`, переданный в `outputs`. Проверки
связывания указывают именно HTML-страницу; пробы, якоря и позиции parse5 относятся
к этому результату. Они не являются номерами строк QMD. Позиция ошибки JSON
также относится к выбранному каталогу, а не к строке исходного документа.
Если входной документ неизвестен, расширение не восстанавливает его по имени
HTML или временному файлу.

## Собственные ID и действия

| ID | Условие | Что проверить |
| --- | --- | --- |
| `QRC.CONFIG_INVALID` | Неверная форма `reference-catalog`, неизвестное поле, некорректный выбор экспорта или namespace портала | Исправьте указанное поле авторской конфигурации. Namespace портала должен отличаться от участников и импортов. |
| `QRC.IMPORT_INVALID` | Неверные настройки импорта, URL, JSON, схема, поля цели или выбранное пространство производителя | Проверьте показанный `source`, поле и namespace. Возьмите текущий каталог публикации производителя; не используйте локальный псевдоним вместо его namespace. |
| `QRC.TARGET_DUPLICATE` | Повторяющаяся пара `namespace:id` | Сообщение показывает обе страницы результатов. Исправьте ID в соответствующих QMD или конфликт пространств имён. |
| `QRC.TARGET_UNKNOWN` | Full не находит ссылку или объявленную экспортируемую цель | Проверьте написание `namespace:id`, текущие `outputs`, выбор экспорта и каталог импорта. Соберите исходный документ цели. |
| `QRC.OUTPUT_INVALID` | Неверный или отсутствующий текущий output, выход из `stage`, неполная проба, неоднозначный якорь или слайд без устойчивого ID | Проверьте список текущих outputs и штатный результат Quarto. Цель Reveal должна находиться внутри слайда с явным ID. |
| `QRC.REFERENCE_INVALID` | Неверный namespace, ID, стиль или разметка ссылки; недоступный числовой стиль; смешанные библиографические ссылки | Исправьте поле ссылки в QMD. Для цели без номера используйте название либо собственную подпись. Ссылки каталога и библиографические ссылки пишите отдельно. |

Например, повторение цели содержит `QRC.TARGET_DUPLICATE`, `ID=book:sec-one`,
`источник=HTML-результат second.html` и связанную страницу `first.html`.
Это две страницы с одной идентичностью, а не две оценки задания.

## Local и full

Самостоятельный `post-render` всегда выполняет **local**, даже при полном
`quarto render` одного компонента. Цели текущих страниц и доступных импортов
разрешаются сразу. Если другой документ или локальный каталог ещё не собран,
ссылка сохраняет подпись и идентичность, получает `data-qrc-deferred="true"`
и пока не получает `href`. Итог выводит число отложенных ссылок как обычную
информацию. Это не предупреждение и не `QRC.TARGET_UNKNOWN`.

Отсутствующий локальный файл или отсутствующий namespace в корректном локальном
каталоге допускают отсрочку. Неверные настройки, повреждённый JSON и отказ HTTP
остаются ошибками. Следующий вызов заново читает источник.

**Full** вызывается через прежний `publish(context)` после успешной сборки
полного текущего набора страниц. Он отклоняет неизвестную цель и отсутствующий
объявленный экспорт, удаляет пробы и публикует `reference-catalog.json`.
В обоих режимах старый HTML вне явных `outputs` не участвует. Local пишет
отдельный `reference-catalog-local.json` и сохраняет пробы для full.

## Внешний отказ и hook

Отказ запуска Quarto, ненулевой exit code, отказ HTTP или чтения файла сохраняют
исходную причину (`cause`). Объект ошибки имеет имя `ExternalToolFailure`,
сохраняет средство (`tool`), exit code (либо `null`, если процесс не завершился),
stdout и stderr. Отказ HTTP показывает статус и тело ответа, включая чужой ID;
ошибка чтения файла сохраняет исходную ошибку файловой системы. Это локальные
Error-объекты, не новый публичный формат отчёта. Чужой ID не преобразуется в
семантический ID QRC.

Exit code 0 остаётся успехом даже при тексте `WARNING` в stderr. Успешный stderr
передаётся без разбора. Строгость `--fail-if-warnings` определяет сам Quarto/Pandoc;
у QRC нет отдельного строгого режима, распознающего предупреждения по тексту.

Hook печатает ожидаемую именованную ошибку один раз, без повторного вывода
внешних потоков. Неизвестное внутреннее исключение сохраняет штатный stack.
Необязательный `COURSE_BUILD_TRACE` записывает только ограниченные метаданные
вызова: отказ журнала не заменяет результат процесса и не раскрывает потоки.

## Демонстрации и исходники

[Группа переходов](../examples/course/README.md) показывает книгу, лекции и
практику; [внешний каталог](../examples/external/README.md) — независимый сайт
с явно помеченным адресным снимком. У каждого проекта свой `lang: ru`.
HTML использует штатное `repo-actions: [source]` с точным QMD; ручная повторная
ссылка удалена. В Quarto 1.10 книга размещает одно действие в боковой панели и
его адаптивную копию для мобильного экрана. Это штатное размещение, а не две
авторские ссылки в тексте. Reveal сохраняет обычную ссылку на исходный QMD.

## Проверка справочника

`tests/diagnostics.ts` проверяет шесть ID через реальные guards: выбранный
источник и поле импорта, namespace/ID, обе страницы дубликата и недоступный
output. `tests/export-context.ts` проверяет Lua на настоящем QMD.
`tests/process-trace.ts`, `tests/import-safety.ts` и `tests/native-local.ts`
проверяют exit 0 с предупреждением, внешний отказ, сохранение причины и чужого
ID, однократный вывод hook и stack неизвестного исключения. Регрессии
`local-linking`, `full-outputs`, `imports`, `local-imports` проверяют прежние
условия, отсрочку и свежесть текущих данных. Код, этот справочник и отрицательные
тесты проверяются вместе при изменении правил.
