# Контракт каталога ссылок

Текущий ref — **3.3.0** (unreleased); версия определяется descriptor того же ref.

Авторская конфигурация `reference-catalog` содержит `namespace`, `imports`, `exports`, `publication`. Неизвестные поля отклоняются. Состав native проектов задаётся отдельно в корневом `subprojects: [paths]`.

`namespace` — локальное имя текущего самостоятельного проекта. Каждый native проект явно задаёт свой namespace в авторском YAML; полный caller передаёт эти namespaces. Управляемый корневой портал сохраняет собственное авторское `reference-catalog.namespace`; оно обязательно, имеет тот же синтаксис, что другие пространства имён QRC, и не совпадает с именем участника или псевдонимом импорта. Только переданный координатором фактический портал добавляет это имя к локальным пространствам имён составной публикации. `imports` сопоставляет локальные псевдонимы источникам JSON; обязательны `source`, `namespace`, `base-url`, необязательны `title`, `style`. `exports` необязателен: без него экспортируются все собственные цели текущих outputs, включая портал и HTML/Reveal-части составной публикации. Явный `exports` сопоставляет собственные пространства спискам ID или `"*"` и экспортирует только этот выбор; пропущенные пространства не экспортируются. `exports: {}` отключает экспорт, пустой список ID не выбирает целей. Импортированные цели не переэкспортируются. Выбор экспорта не ограничивает локальные ссылки и не включает сохранённые HTML вне текущих outputs. `publication.title` — название публикации.

Результат `reference-catalog.json` содержит текущую схему `quarto-reference-catalog`, сведения о Quarto, необязательное название публикации и `targets`. Ключ цели имеет вид `namespace:id`. Цель хранит относительную страницу, HTML ID, подпись и номер; для Reveal — также ID слайда. Модель JSON задаёт [исполняемый TS validator](../_extensions/reference-catalog/infrastructure/catalog-validation.ts); отдельной ручной JSON-схемы нет. При импорте дополнительные metadata поля каталога,
`generator`, `publication` и целей игнорируются; потребитель получает только
проверенные поля текущей модели. Обязательные поля, их типы, схема и адреса
проверяются по-прежнему. Поля цели `baseUrl`, `sourceTitle` и `defaultStyle`
в импортируемом JSON запрещены: их задаёт конфигурация импорта, а не публикация.
Состав собственного экспортируемого JSON этим допуском не расширяется.

Самостоятельная сборка требует явного подключения фильтра и `entrypoints/post.ts`. Расширение не добавляет проектных обработчиков при установке. Проект составной публикации передаёт явный текущий список outputs и поисковых индексов в `infrastructure/publish.ts` с `scope: "full"`. Оба режима требуют `outputs`; retained HTML вне списка не учитывается. Импорт в PDF не реализуется: QRC разрешает ссылки в веб-публикации; PDF-раздатка доступна по обычным ссылкам на файл.

До первой записи `publish` готовит и проверяет весь результат HTML, search и
каталога. Ошибка входного индекса или ссылки сохраняет исходные байты stage;
после исправления входа публикацию можно повторить в том же stage. В full
каждый переданный поисковый индекс и объединённый корневой search содержат
только строки текущих HTML outputs. Относительные href, фрагменты и metadata
исходных строк сохраняются в mounted индексах. Если один физический индекс
передан с несколькими mounts, строки общие, текст обновляет последний mount,
а full сохраняет лишь строки, текущие во всех этих представлениях. Local
обновляет текущие страницы, сохраняя строки остальных страниц.

Применение подготовленных файлов выполняется последовательно. При ошибке
файловой системы исходный отказ передаётся вызывающему коду, уже записанные
файлы остаются изменёнными; атомарное переключение всего stage не обещается.
Повтор после такого отказа требует исправить причину записи и передать
полноценные текущие результаты Quarto, если часть HTML уже финализирована.

Публичные поля определены в `domain/contract.ts`; единственный словарь стилей — `vocabulary/reference-styles.json`, его статические проекции для TypeScript и Lua создаёт `tools/generate-vocabulary.ts`; перечень типов целей Quarto — в `lua/constants.lua`. При пользовательских типах crossref фильтр дополняет встроенный словарь из штатных метаданных Quarto.

Путь размещения выводится из нормализованной папки подпроекта; namespace задаётся независимо в его `reference-catalog`. Разные папки `a/slides` и `b/slides` не требуют namespace со слешем. Эффективные пользовательские HTML/Revealjs форматы выбирает native Quarto; QRC получает текущие готовые HTML и не переопределяет формат документа. `.task-items` остаётся списком назначений Core: QRC связывает ссылки на условия и не переносит их тела.

Полный исходный вход Core включает `course-export-context: true` только в служебном экспортном рендере. В нём ссылки QRC превращаются в native Span с data-qrc-ref/style/custom и авторским текстом, без фиктивного href. Это сохраняет ссылки до отбора назначений; выбранный body producer разрешает поддержанную цель или выдаёт явную диагностику. Обычный невеб-рендер QRC по-прежнему не поддерживается.

## Диагностика и причины отказа

[Справочник диагностики](diagnostics.md) закрепляет собственные ID, доступный
контекст и действия автора. Сигнатура `publish(context: CatalogPublication):
Promise<void>` и API маркеров сохраняются. Внутренний formatter возвращает
обычный Error с `code` и именем `ExtensionDiagnostic`; внешние отказы имеют
имя `ExternalToolFailure` и сохраняют средство, exit code, потоки и причину.
Эти объекты не являются сериализованным публичным отчётом.

`source` импорта указывает JSON, входной QMD известен Lua, а `outputs` указывает
текущие результаты Quarto. Нельзя трактовать позиции JSON или HTML как строки
QMD. Отсрочка local остаётся информационным результатом; full требует полного
разрешения целей. Строгость предупреждений задаётся параметрами Quarto/Pandoc.

## Банк Core и student/full

QRC переносит только идентичность и адрес цели. Он не импортирует условия,
решения, assignments или grading payload; общий банк принадлежит
[Core](../../quarto-course/spec/index.md). Restricted задача удалена из
student-проекции и не оставляет цель, подпись или текст условия в её каталоге
и поиске. Full каталог строится из текущего full набора и может содержать адрес.
Выбор `exports` управляет адресами каталога, а не публикацией условий.

Строгий full отклоняет явно выбранную недоступную цель с `QRC.TARGET_UNKNOWN`;
local сохраняет отсрочку без фиктивного href. `.assessment-preview` содержит
обычные ссылки сайта; его исключение из Body выполняет producer Core.
В служебном source export QRC сохраняет нейтральную native идентичность ссылок,
не копируя чужое условие. `publish(context)` сохраняет current outputs,
containment, strict full и общий проход linking/search.

[Демонстрации](../README.md) не подключают Core. Их native exr/exm/sol остаются
обычными Quarto объектами без обязательных банковских difficulty/time.

## Семантика HTML metadata

Чтение и финализация HTML используют имена и значения атрибутов QRC;
порядок атрибутов не задаёт семантику ссылок и проб. Дополнительная
сортировка готового HTML не выполняется. Local сохраняет probes и metadata
для последующей финализации; full удаляет контейнеры probes.
Значения, подписи, URL и авторская разметка сохраняются по правилам linking.

При создании native Pandoc Attr карты Lua пока преобразуются в
отсортированные списки пар. Этот порядок сериализации не является
требованием к порядку атрибутов входного или итогового HTML.

## Публичная адресация Body (unreleased)

`entrypoints/body-links.ts` предоставляет `createBodyLinks({catalog, baseUrl})`
и `loadBodyLinks({catalogFile, baseUrl, root, namespace, imports})`.
Возвращаемый `resolve(key, style, source)` выдаёт `{href, label}` по тем же
проверкам target и алгоритму URL, что веб-публикация, включая вложенные
цели Reveal и стили подписей. Base URL обязан быть HTTP(S) и заканчиваться `/`.
Loader использует обычную проверку каталогов/импортов; неизвестная обязательная
цель сохраняет диагностику QRC и source. Он не читает тела заданий и не
добавляет repository metadata overlay. Core удаляет self-target и разделяет
публичный/закрытый AST; native consumer задаёт политику новых вкладок.

## Контекст наблюдения (3.1.1, unreleased)

Фасад ABI 1 передаёт `attributes.extension_id: "reference-catalog"`.
Необязательный `document_id` задаётся только при однозначном документе:
нативные обработчики Lua `requests`/`probes` читают публичный
`quarto.doc.input_file` при каждом вызове, без пустого или отсутствующего
значения; `readPage(path, html)` передаёт явный путь обрабатываемого output.
Контекст не преобразует входной QMD в выходной HTML или обратно.
Пакетный `publish(context)` не назначает себе один произвольный документ
из `outputs`; его local/full проверки сохраняются.

Только при активном контексте агента полный снимок окружения с явными
переопределениями передаётся через `childEnv` и `clearEnv: true`. Это сохраняет рабочие переменные
и исключает повторное наследование удалённого устаревшего
`COURSE_PERF_PARENT_SPAN_ID`. Контекст родителя соответствует текущему активному
span. Identity-ответ (`off`, отсутствующий агент или недоступное чтение режима)
сохраняет прежние env overrides, native inheritance и разрешения без нового
полного чтения env и `clearEnv`. Исходные функции, Promise и окружение фасада
сохраняются. Этот
контракт не вводит общий runtime и не заявляет полного семантического покрытия
QRC; авторская конфигурация и схема каталога остаются прежними.

## Согласованность типов

Типы `Catalog`, `Import` и `Exports` выводятся из фактических guard outputs;
`Target` дополняет проверенную publication цель полями существующей runtime
projection импорта. Ручные интерфейсы не задают второй контракт. Нормализация,
порядок отказов и диагностика сохранены. `tests/contract-consistency.ts` проверяет
весь public graph и намеренно меняет numeric guard только в новом scratch: consumer
typecheck обязан обнаружить реальный drift. Статическая проверка не заменяет
actual import/export/installed example и позднюю межкомпонентную приёмку.
