# Книга и две презентации

Пример использует native root website и опциональный course-site, поставляемый
репозиторием quarto-project-publish. Текущие кандидаты — QRC 3.1.1 и Site 5.1.4
(**unreleased**). До публикации тегов проверяйте целые локальные checkout;
`task install` применяется после их публикации. Hooks используют GitHub namespace
Afonenko-Course-Tools.

```sh
task install
task render
```

Hooks уже используют `_extensions/Afonenko-Course-Tools/…`. Каждая часть явно подключает QRC и свой
namespace. Root index.qmd остаётся обычной главной страницей; книга, лекции и
практика перечисляются в `subprojects` и размещаются по путям `book`, `lectures`, `practice`. Двусторонние ссылки
строго разрешаются после успешной полной native сборки. Самостоятельный
`quarto render chapter.qmd` внутри части использует local связывание.

Ресурсы книги и лекций лежат внутри своих native проектов: `book/assets/`
и `lectures/assets/`. Относительная ссылка из вложенной страницы использует
`../assets/…`, поэтому ресурс попадает и в отдельный output части, и в её mount.
Исходные QMD текущих групп подготовлены для тега `v3.1.1`.

Блок `reference-catalog.exports` не нужен: каталог включает все собственные
цели текущих страниц корня, книги, лекций и практики по умолчанию.

`task render` записывает `_site/BUILD.json`: точная ревизия производителя,
закреплённые зависимости и версия Quarto. Исторический архив `catalog-cross-project.tar.gz`
в неизменяемом выпуске `demo-20261008` соответствует прежнему тегу v3.0.0;
он и его исходные receipts сохраняются. Текущий кандидат не пересобирает этот
архив. Новая готовая группа требует собственных source/tag/archive/install
проверок после публикации нового тега.

В каждом самостоятельном проекте `lang: ru` задаётся явно. HTML использует
штатное действие Quarto `repo-actions: [source]`: оно ведёт к точному QMD
в закреплённой группе и заменяет повторявшуюся ручную ссылку. Reveal сохраняет
обычную ссылку на исходный QMD, поскольку действие HTML к слайдам не применяется.

Ошибка ссылки показывает namespace/ID и текущую страницу результата;
[справочник диагностики](../../docs/diagnostics.md) объясняет исправление.
Самостоятельная сборка QRC остаётся local: отсутствующая цель откладывается,
а повреждённый каталог или HTTP-отказ останавливает сборку. Полная составная
финализация строго проверяет текущие outputs. Источник JSON и `base-url`
публикации остаются независимыми; адреса готовых групп не меняются.

Источники текущего кандидата используют v3.1.1 и Quarto 1.11.5.
Готовый asset допускается к публикации только с
точным producer commit и `sourceDirty: false` в `BUILD.json`.
В этих проектах Core банк не включён: native exr/exm/sol сохраняют обычные правила Quarto.
